# Шахматы 2 на 2 — техническое задание (MVP)

Цель: онлайн-игра по ссылке. Один человек создаёт комнату, кидает ссылку друзьям, все открывают её в браузере (телефон/ноутбук) и играют в реальном времени. Регистраций нет.

## 0. Ключевые решения (не менять без причины)

1. **Архитектура: один Node.js-процесс** — отдаёт статическую страницу и держит WebSocket-соединения. Сервер — единственный источник правды (валидирует ходы, рассылает состояние). Клиент — один файл `public/index.html` без сборки и фреймворков.
2. **Правила шахмат — библиотека `chess.js@0.10.3`** (пин версии обязателен, у 1.x другие имена методов). Используется и на сервере (валидация), и на клиенте (подсветка легальных ходов). На клиент отдаём копию из `node_modules/chess.js/chess.js` как `/chess.js` — никаких CDN.
3. **Протокол: сервер после любого изменения шлёт всем в комнате полное состояние** (`{t:'state', room}`), никаких дельт. Просто и устойчиво к реконнектам.
4. **Идентификация игрока — случайный `playerId` в localStorage + ник.** После перезагрузки страницы игрок автоматически возвращается на своё место.
5. **Хостинг**: песочница Claude не умеет открывать публичный порт, поэтому ссылка появится после запуска у пользователя (см. раздел 8). Код не привязан к хостеру: `PORT` из env, без Docker, без БД.

Почему не Claude-артефакт: страница-артефакт не может открывать WebSocket/WebRTC наружу, а встроенные realtime-возможности (`room`/`db`) не работают для людей, открывших публичную ссылку без аккаунта Claude.

## 1. Правила «2 на 2»

- Одна доска, 4 места: `w1`, `w2` (белые), `b1`, `b2` (чёрные).
- Партнёры ходят по очереди. Порядок: w1, b1, w2, b2, w1, b1, …
- Если на стороне занято только одно место, этот игрок ходит за сторону всегда (режим вырождается в 1 на 1 или 2 на 1 — это нормально).
- Если на стороне никого нет — ходы этой стороны заблокированы, статус «ждём игроков».
- Полные правила шахмат через chess.js: рокировка, взятие на проходе, превращение (игрок выбирает фигуру), шах, мат, пат, ничья по 50 ходам / троекратному повторению / недостатку материала.
- Сдаться может любой игрок стороны (`resign`) — победа соперников. Предложение ничьей — не в MVP.
- Реванш (`newgame`): позиция сбрасывается, цвета меняются (w1↔b1, w2↔b2).
- Все, кто открыл ссылку, но не сел за доску — зрители (видят всё, ходить не могут).

Алгоритм «чей ход» (сервер, функция `expectedSeat(room)`):
```
side = chess.turn()                     // 'w' | 'b'
n = число уже сделанных ходов этой стороны
first  = n % 2 === 0 ? side+'1' : side+'2'
second = (first === side+'1') ? side+'2' : side+'1'
return seats[first] ? first : (seats[second] ? second : null)
```
Ход принимается, только если `room.seats[expectedSeat] === playerId` отправителя и `chess.move(...)` вернул не `null`.

## 3. Модель комнаты (сервер)

```js
room = {
  id: 'k7m2xq',                 // 6 символов из алфавита без 0/O/1/l/I
  createdAt, updatedAt,         // ms
  fen: 'rnbqkbnr/...',          // текущая позиция
  moves: [{ from, to, promotion, san, side: 'w'|'b', seat: 'w1', playerId, ts }],
  seats: { w1: playerId|null, w2: null, b1: null, b2: null },
  players: { [playerId]: { name, connected: true|false, lastSeen } },
  status: 'waiting' | 'playing' | 'finished',
  result: null | { winner: 'w'|'b'|null, reason: 'checkmate'|'stalemate'|'draw'|'resign' }
}
```
- В памяти: `Map<roomId, room>` + `Map<roomId, Set<ws>>`. У каждого `ws` храним `ws.playerId`, `ws.roomId`.
- `status` = `playing`, как только есть хотя бы один игрок с каждой стороны; `waiting`, если нет.
- Персистентность: после каждого изменения — отложенная (debounce 1 с) запись всех комнат в `data/rooms.json`; при старте — загрузка. Раз в час удалять комнаты, где `updatedAt` старше 48 ч.
- Сокеты: ping каждые 30 с, не ответившие — закрывать, игрока помечать `connected:false` (место за ним остаётся).

## 4. Протокол (JSON по WebSocket, одно соединение на вкладку)

Клиент → сервер:
- `{t:'join', room, playerId, name}` — вход в комнату (и после каждого реконнекта). Если комнаты нет — создать.
- `{t:'sit', seat:'w1'|'w2'|'b1'|'b2'}` — занять свободное место (одновременно только одно место на игрока).
- `{t:'stand'}` — встать.
- `{t:'move', from:'e2', to:'e4', promotion:'q'|'r'|'b'|'n'|undefined}`.
- `{t:'resign'}`, `{t:'newgame'}`, `{t:'rename', name}`.

Сервер → клиент:
- `{t:'state', room, you: playerId}` — всем в комнате после каждого изменения и каждому при `join`.
- `{t:'error', code:'not_your_turn'|'illegal_move'|'seat_taken'|'bad_request', msg}` — только отправителю.

Сервер никому не доверяет: любое сообщение проверяется, мусор игнорируется с `error`.

## 5. Сервер (server.js)

- `http.createServer`: `GET /` и `GET /r/<id>` → `public/index.html`; `GET /chess.js` → файл; остальное 404. Заголовок `Cache-Control: no-store` для html.
- `new WebSocketServer({ server })`; URL сокета на клиенте — тот же хост (`ws://` или `wss://` по `location.protocol`).
- Обработка `move`: `const chess = new Chess(room.fen)`; проверить `expectedSeat`; `const m = chess.move({from,to,promotion})`; если `null` → `illegal_move`; иначе `room.fen = chess.fen()`, добавить ход, проверить конец партии: `in_checkmate()` → победил только что ходивший; `in_stalemate()` / `in_draw()` → ничья; обновить `status/result`, разослать `state`.
- API chess.js 0.10.3, которое нужно: `new Chess(fen)`, `turn()`, `fen()`, `move({from,to,promotion})` → объект или `null`, `moves({square, verbose:true})`, `in_check()`, `in_checkmate()`, `in_stalemate()`, `in_draw()`, `game_over()`, `get(square)`, `history({verbose:true})`.

## 6. Клиент (public/index.html)

Экраны:
1. `/` — заголовок, кнопка «Создать игру» → генерирует id, `location.href = '/r/' + id`. Поле «Войти по коду» (вставить код комнаты).
2. `/r/<id>` — комната. Первый визит: модальное окно «Как тебя зовут?» (ник в localStorage). Дальше:
   - верхняя полоса: код комнаты, кнопка «Скопировать ссылку», индикатор соединения;
   - доска 8×8 (квадрат, `min(92vw, 60vh)`), фигуры — Unicode-символы ♔♕♖♗♘♙/♚♛♜♝♞♟ крупным размером; доска перевёрнута, если я сижу за чёрных;
   - два ряда мест: «Белые: [w1] [w2]», «Чёрные: [b1] [b2]»; свободное место — кнопка «Сесть», занятое — ник + точка онлайн/офлайн, своё — кнопка «Встать»; место, чей ход сейчас, подсвечено;
   - строка статуса: «Ход: Маша (белые)», «Шах!», «Мат. Победили чёрные», «Пат — ничья», «Ждём второго игрока…»;
   - кнопки «Сдаться», «Новая партия»; список ходов (SAN, компактно, прокручиваемый).
- Взаимодействие: тап по своей фигуре (только когда ход мой) → подсветка легальных клеток (`chess.moves({square, verbose:true})`) → тап по целевой клетке → если превращение — всплывашка выбора ферзь/ладья/слон/конь → отправка `move`. Последний ход подсвечен; король под шахом подсвечен красным. Ход отображается только после прихода `state` от сервера (без оптимистичного применения).
- Реконнект: при `close` переподключаться с задержкой 1, 2, 4… до 15 с, после открытия снова слать `join`. Пока нет соединения — доска заблокирована, индикатор красный.
- Мобильная вёрстка по умолчанию, тёмная и светлая тема через `prefers-color-scheme`, весь UI на русском.

## 7. Автотест (test/play.test.js)

Запускает сервер на случайном порту, открывает 2 ws-клиента:
1. оба `join`, садятся на `w1` и `b1`;
2. разыгрывают детский мат (e4 e5 Qh5 Nc6 Bc4 Nf6 Qxf7#) → ожидаем `status==='finished'`, `result.winner==='w'`;
3. ход вне очереди → `error not_your_turn`; нелегальный ход → `illegal_move`;
4. третий клиент делает `join` в ту же комнату → сразу получает актуальный `state`;
5. `newgame` → цвета поменялись, `moves.length===0`.
Выход с кодом 0/1. Запускать после каждого изменения сервера. Для клиента — хотя бы `node --check` на вырезанном скрипте или открытие страницы в браузере, если он доступен.

## 8. Запуск и публикация ссылки (README.md)

- Локально: `npm install && npm start` → `http://localhost:3000`.
- Показать друзьям прямо сейчас (компьютер должен быть включён): туннель к локальному серверу — `ssh -R 80:localhost:3000 nokey@localhost.run` (без регистрации) или `ngrok http 3000`, или `cloudflared tunnel --url http://localhost:3000`. Полученный https-адрес и есть ссылка.
- Постоянно и бесплатно: Render.com (Web Service из GitHub-репозитория, free-план; засыпает через 15 мин простоя, первое открытие ждёт ~30–60 с) или любой VPS (`pm2 start server.js`). Диск на free-планах не сохраняется между перезапусками — комнаты старых партий могут пропасть, это допустимо.
- Cloudflare Workers + Durable Objects тоже подходят, но требуют переписать транспорт, а домен `workers.dev` в России открывается не у всех — только со своим доменом.

## 9. После MVP (не делать в первой версии)

Часы (общие на сторону, серверное время), предложение ничьей, чат в комнате, звук хода, экспорт PGN, счётчик зрителей, «шведки»/bughouse (две доски + сброс взятых фигур — chess.js это не умеет, нужен свой движок).

## 10. Отличия реализации от ТЗ (v1)

- npm-пакеты в песочнице недоступны, поэтому проект без зависимостей: вместо chess.js — свой `public/rules.js` (проверен perft-тестами), вместо `ws` — минимальный WebSocket в `server.js`. API правил совместимо по смыслу: `moves({square, verbose})`, `move()`, `inCheck()`, `isCheckmate()`, `outcome()`.
- Вместо `playerId` клиент хранит секретный `token`; в состоянии комнаты виден только публичный id (хэш токена), чтобы нельзя было выдать себя за другого игрока.
- Сокет-эндпоинт — `/ws`; файл правил отдаётся как `/rules.js`; есть `/healthz`.
